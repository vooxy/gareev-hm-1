## Команды, которые я использовал

| Команда | Что делает |
|---------|-----------|
| `git status` | Показывает ветку и состояние файлов |
| `git add` | Кладёт изменения в область подготовки |
| `git commit -m "..."` | Делает снимок с сообщением |
| `git switch` / `git switch -c` | Переключается на ветку / создаёт новую |
| `git pull` / `git push` | Забирает / отправляет снимки на GitHub |
| `git merge` | Сливает ветку в текущую |
| `git diff` | Показывает, что изменилось |
| `git log --oneline --graph --all` | Показывает граф истории |
| `git branch -d` | Удаляет влитую ветку |

## С какими трудностями столкнулся

- **Закрыл терминал посреди работы.** Оказалось, это не страшно: ветки и снимки хранятся в папке проекта. Достаточно снова зайти в папку командой `cd` и проверить ветку.
- **Блокнот Windows 11 испортил разметку Markdown:** добавил обратные косые черты перед `#` и `*`. Исправил, записав файлы через `cat` в Git Bash, и отдельным снимком `docs: исправить разметку Markdown`.
- **При создании PR GitHub по умолчанию предлагает `main`.** По Git Flow фичи идут в `develop`, поэтому base нужно менять вручную.

## Главный вывод

Работу никогда не делаю прямо в `main` или `develop`: только в `feature/*` от свежего `develop`, а затем Pull Request в `develop`. В `main` код попадает только через `release/*` или срочный `hotfix/*`.
